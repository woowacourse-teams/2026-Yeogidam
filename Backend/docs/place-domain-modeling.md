# place 패키지 도메인 모델링

릴스에서 추출된 장소를 자바 객체로 어떻게 표현했는지, 왜 그렇게 나눴는지를 기록한다.
US-01(공유로 저장)과 US-02(장소 다시 보기)를 구현하면서 정리된 구조이며 필드 구성은 운영 중인 수파베이스 places 테이블을 참고 기준으로 삼았다.

## 전체 구조

```
Place                       장소 하나. 내부 식별자, 외부 정체성, 프로필로 이루어진다
├── PlaceExternalSource     외부(카카오) 정체성 (record). placeId는 필수, placeUrl은 불량이면 null로 정규화
└── PlaceProfile            외부에서 받아와 채우는 표시 정보 (record)
    ├── PlaceName           이름. 비어 있으면 생성이 거부된다
    ├── Address             지번 주소와 도로명 주소. 지번은 필수다
    ├── Coordinate          위도와 경도. 범위를 벗어나면 생성이 거부된다
    ├── category            문자열 그대로 담는다
    ├── telephone           문자열 그대로 담는다
    └── PlaceThumbnail      사진 url, 출처, 저작권 표기 세 값의 묶음 (record)
```

경계 쪽 객체는 place.service 패키지에 있다. CandidatePlaceName은 AI가 뽑은 장소 이름 후보이고, SearchedPlace는 지도 검색(카카오) 어댑터가 돌려주는 산출물이며, PlaceSearcher는 그 어댑터의 포트 인터페이스다. DB 쪽 표현인 PlaceRecord와 SavedPlaceRecord는 place.repository에 있고 도메인 객체와 분리되어 있다.

## 객체별 책임

| 객체 | 형태 | 책임 |
|---|---|---|
| Place | 클래스 | 내부 식별자, 외부 정체성, 프로필을 묶고 주소 요약 같은 행동을 제공한다 |
| PlaceExternalSource | record | 카카오에서의 이 장소의 정체성. placeId 필수를 보장하고 불량 placeUrl을 null로 정규화한다 |
| PlaceProfile | record | 외부에서 받아온 장소 정보를 한 덩어리로 든다. 이름, 주소, 좌표가 없으면 생성이 거부된다 |
| PlaceName | record | 이름이 비어 있지 않음을 보장한다 |
| Address | record | 지번 필수를 보장하고, 빈 도로명을 null로 정규화하며, 화면 표기 규칙("도/시 시/군/구"까지)의 요약을 만든다 |
| Coordinate | record | 위도 ±90, 경도 ±180 범위를 보장한다 |
| PlaceThumbnail | record | 사진 url과 출처와 저작권 표기를 함께 나른다. 검증하지 않는다 |
| SearchedPlace | record | 카카오 검색 산출물을 검증 없이 나른다 |
| PlaceRecord | record | place 테이블 한 행. DB 전용 표현이다 |

## 왜 이렇게 나눴나

### 1. Place는 내부 식별자, 외부 정체성, 프로필 셋으로 가른다

장소의 값은 식별자를 빼면 전부 외부(카카오 검색, 사진 출처)에서 받아온다. 받아온 값 중에서도 성격이 갈리는데, 카카오 place id는 이 장소가 카카오 세계에서 누구인지를 가리키는 정체성이고 다음 cycle의 중복 제거 키가 될 값이라, 표시 정보 묶음(PlaceProfile)과 분리해 PlaceExternalSource로 뒀다. Reel이 외부 정체성인 InstagramUrl을 프로필 속이 아니라 몸통에 직접 드는 것과 같은 그림이라, 두 집합체가 "내부 식별자 + 외부 정체성 + 정보"라는 모양을 공유한다. 프로필에 필드가 늘어도 Place의 모양은 변하지 않는다.

### 2. 검증은 "깨졌을 때 실패시켜서 얻는 것이 있는 값"에만 건다

외부 API가 주는 값은 사용자 입력과 달리 잘못됐을 때 되돌려 줄 상대가 없다. 검증에 실패시키면 우리가 할 수 있는 일은 그 장소를 버리는 것뿐이므로 버릴 가치가 있는 값만 검증한다.

- 이름: 카드, 검색, 핀 묶기가 전부 이름에 걸려 있어 이름 없는 장소는 쓸모가 없다. 검증한다.
- 좌표: 좌표가 불량이면 지도에 틀린 핀이 찍힌다. 틀린 정보를 보여주는 것은 안 보여주는 것보다 나쁘므로 검증한다.
- 지번 주소: 요약 표기의 입력이자 정보 화면의 필수값이라 검증한다.
- 외부 장소 식별자(placeId): 다음 cycle에 중복 제거 키로 쓰일 값이라 비어 있으면 검증에서 거른다. 키가 비면 우리 시스템의 판단이 깨진다.
- 외부 장소 URL(placeUrl): 바로가기 버튼용 표시 값이라 버릴 가치가 없다. 대신 형식이 불량이면 null로 정규화해 버튼만 포기한다. 예외 대신 정규화가 이 값의 도구다.
- 전화번호, 카테고리, 사진: 이상해도 그 칸만 이상하게 보이고 끝이라 담기만 한다. 전화번호에 정규식을 걸면 카카오가 예상 밖 형식(1588 국번, 국제번호)을 주는 순간 멀쩡한 장소가 통째로 실패한다.

여기서 정합성의 정의가 나온다. Place에는 정합한 장소만 담기지만, 정합은 "모든 필드가 nonnull"이 아니라 "필수 필드(이름, 좌표, 지번, placeId)가 nonnull"이다. 전화번호 없는 가게와 도로명 없는 주소는 현실에 존재하므로, 그 필드들의 null은 불량이 아니라 없음이라는 정보다. 모든 칸을 필수로 올리면 현실의 멀쩡한 장소가 도메인에 못 들어온다.

참고한 프로젝트들도 같은 결을 보인다. 토스 응답을 담는 PaymentResult는 record 경계에서 검증하지 않고 정말 중요한 금액 일치는 도메인 규칙에서 따로 검사한다.

### 3. Address는 지번과 도로명을 함께 가진다

지번과 도로명은 한 장소의 주소라는 같은 개념의 두 표기라서 한 객체로 묶었다. 지번은 요약 규칙과 화면 필수값이라 반드시 있어야 하고, 도로명은 없을 수 있으므로 빈 문자열이 들어오면 null로 정규화한다. 요약 규칙("서울 성동구 성수동2가 289-10" → "서울 성동구")은 화면 명세의 표기 규칙을 그대로 코드로 옮긴 것이다.

### 4. Coordinate는 double이 아니라 BigDecimal이다

DB 컬럼이 DECIMAL(13, 10)이고 지도 핀을 묶을 때 좌표 동등 비교를 SQL에서 한다. double을 쓰면 저장과 조회를 오가며 부동소수점 오차가 끼어들 수 있어 저장부터 비교까지 한 타입으로 오차 없이 흐르도록 BigDecimal로 통일했다.

### 5. PlaceThumbnail은 세 값이 함께 다닌다

수파베이스는 thumbnail_url, thumbnail_source, photo_attribution 세 컬럼을 항상 같이 둔다. 사진의 출처(카카오, 구글, 인스타그램)에 따라 저작권 표기 의무가 달라지기 때문에 url만 따로 다니면 표기를 빠뜨리기 쉽다. 그래서 세 값을 한 record로 묶어 같이 다니게 했다.

### 6. 검증 시점은 조회 때가 아니라 저장 전이다

파이프라인의 쓰기 경로는 SearchedPlace를 DB 표현으로 바로 옮기므로 값 객체를 거치지 않는다. 그대로 두면 불량 값이 조용히 저장됐다가 나중에 사용자가 장소 선택을 누르는 순간 도메인 복원 과정에서 500으로 터진다. 원인(저장)과 증상(며칠 뒤 클릭)이 멀어서 찾기도 어렵다.

그래서 매칭 단계 끝에 검문을 둔다. 저장 직전에 PlaceName, Address, Coordinate 생성을 시도해 보고 예외가 나는 장소만 제외한다. 값 객체 생성이 곧 검증이므로 검사 규칙을 중복으로 적을 필요가 없고 불량 장소는 그 릴스에서만 빠지며 나머지 장소는 그대로 저장된다. 전부 불량이면 기존 실패 경로(지도에서 장소를 찾지 못했어요)로 떨어진다.

### 7. 도메인과 DB 표현은 분리한다

PlaceRecord는 place 테이블 한 행을 그대로 옮긴 평평한 record이고 도메인 Place는 규칙에 따라 값 객체로 뭉친 구조다. 둘을 잇는 조립 지점(InstagramMediaReader)이 명시적으로 존재해서 DB 컬럼이 늘어도 도메인이 끌려가지 않고 그 반대도 마찬가지다.

## 남은 결정

- 장소를 전역 테이블로 올리고 kakao_place_id로 중복을 제거하는 구조 이전. 중복 공유 요구가 들어오는 다음 cycle에 한다.
- 구글 사진 폴백 어댑터. PlaceThumbnail과 스키마 컬럼은 준비되어 있고 어댑터 구현만 남았다.
- 검문에서 걸러진 불량 장소의 관측. 지금은 흔적이 남지 않으므로 로깅 계층이 생길 때 걸러진 장소와 사유를 남긴다.
