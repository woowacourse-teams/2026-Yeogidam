# 장소 필터 카테고리 칩 분류 기준

- 결정 기록: ADR-02
- 최초 결정 및 최종 수정: 2026-10-28
- 구현 기준: 이슈 #473의 `PlaceCategory`와 `PlaceCategoryClassifier`
- 관련 이슈: [#473](https://github.com/woowacourse-teams/2026-Yeogidam/issues/473), [#296](https://github.com/woowacourse-teams/2026-Yeogidam/issues/296)

## 문서의 목적

보관함과 지도에서 사용할 필터 칩을 왜 11개로 정했는지, 카카오 카테고리를 어떤 기준으로 묶는지 기록한다.
카테고리를 추가하거나 분류 범위를 바꿀 때 이 문서에서 기존 결정의 이유와 영향을 확인한다.
아래 매핑은 문서 작성 시점의 코드 기준이다. 규칙을 변경하면 코드, 테스트, 이 문서를 함께 수정한다.

## 11개 칩을 정한 이유

사용자가 저장한 장소에서 자주 쓰이는 카테고리를 중심으로 다음 필터를 정했다.

**카페, 디저트, 한식, 양식, 일식, 중식, 분식, 술집, 별미, 문화/여가, 기타**

선정에 참고한 자료는 [장소 카테고리 분포](https://claude.ai/artifact/Ci1hV62kENWmdH2Au2zLsg)다.
자료의 조회 시점은 **2026-10-27 15:44:23 KST**이며, 전체 장소 10,818곳과 저장 행 1,841행을 집계했다.
`places`는 장소 수이고, `saved_places`는 회원이 저장한 행 수다. 같은 장소를 여러 회원이 저장하면 저장 행은 여러 번 센다.

| 관측한 내용 | 분류에 반영한 이유 |
| --- | --- |
| 첫 마디가 `음식점`인 장소가 전체 장소의 98.1%, 저장 행의 89.8%였다. | 음식 관련 필터를 세분화한다. |
| 음식점의 상위 8개 두 번째 마디가 전체 장소의 93.1%를 차지했다. | 카페, 간식, 한식, 양식, 일식, 중식, 분식, 술집을 각각 구분한다. 앱에서는 간식을 디저트로 표시한다. |
| 카페는 전체 장소의 21.9%였지만 저장 행에서는 36.0%였다. | 전체 장소 수와 함께 실제 저장 비중을 고려한다. |
| 첫 마디가 `음식점`이 아닌 값도 저장 행의 10.2%였다. | 음식 외 방문 장소를 문화/여가로 묶고, 여기에 해당하지 않는 장소는 기타로 둔다. |

음식 관련 칩은 위 8개와 별미를 합쳐 9개다. 별미는 아시안, 뷔페, 퓨전 음식 등 나머지 음식점을 묶는다.
문화/여가는 박물관, 미술관, 보드카페, 찜질방, 소품샵, 서점, 쇼핑몰, 자연 명소, 숙소 등을 찾기 위한 묶음이다.
이 예시는 방문 목적을 설명한 것이며, 개별 장소의 실제 칩은 아래 카카오 원문 경로로 결정한다.

자료에 나온 수치는 당시 분포를 설명하는 근거다. 현재 운영 개수나 칩별 고정 개수를 뜻하지 않는다.
자료의 검토 제안과 별도로, 실제 적용 규칙은 아래 매핑과 코드에 따른다.

## 칩 목록과 카카오 카테고리 매핑

`>`로 구분한 각 항목을 이 문서에서는 "마디"라고 부른다.
예를 들어 `음식점 > 카페 > 커피전문점`의 첫 마디는 `음식점`, 두 번째 마디는 `카페`다.

표의 "하위 포함"은 경로가 같은 마디로 시작하면 뒤에 세부 업종이나 브랜드 이름이 더 붙어도 같은 칩으로 분류한다는 뜻이다.
글자 일부가 들어 있는지를 검사하는 방식은 아니다.

아래 순서가 칩 목록 API의 반환 순서다. 코드는 `PlaceCategory`의 이름과 같다.

| 순서 | 칩 | 코드 | 카카오 원문 규칙 |
| --- | --- | --- | --- |
| 1 | 카페 | `CAFE` | `음식점 > 카페`와 하위 경로. 단독 `카페`도 포함한다. |
| 2 | 디저트 | `DESSERT` | `음식점 > 간식`과 하위 경로. 단독 `간식`도 포함한다. |
| 3 | 한식 | `KOREAN` | `음식점 > 한식`과 하위 경로. 단독 `한식`도 포함한다. |
| 4 | 양식 | `WESTERN` | `음식점 > 양식`과 하위 경로. 단독 `양식`도 포함한다. |
| 5 | 일식 | `JAPANESE` | `음식점 > 일식`과 하위 경로. 단독 `일식`도 포함한다. |
| 6 | 중식 | `CHINESE` | `음식점 > 중식`과 하위 경로. 단독 `중식`도 포함한다. |
| 7 | 분식 | `BUNSIK` | `음식점 > 분식`과 하위 경로. 단독 `분식`도 포함한다. |
| 8 | 술집 | `BAR` | `음식점 > 술집`과 하위 경로. 단독 `술집`도 포함한다. |
| 9 | 별미 | `SPECIALTY` | 첫 마디가 `음식점`이고 두 번째 마디가 위 8종에 없는 경로. 단독 `음식점`도 포함한다. |
| 10 | 문화/여가 | `CULTURE_LEISURE` | 다음 절의 11개 허용 경로와 그 하위 경로. 단독 `관광명소`도 포함한다. |
| 11 | 기타 | `ETC` | 어느 규칙에도 해당하지 않는 원문, null, 빈 문자열, 공백뿐인 문자열, 빈 마디가 있는 경로. |

### 음식점은 두 번째 마디로 구분한다

첫 마디가 정확히 `음식점`이면 두 번째 마디만으로 음식점 8종을 구분한다.
그 아래에 어떤 업종이나 브랜드가 붙어도 이 분류를 유지한다.

- `음식점 > 카페 > 테마카페 > 디저트카페`는 카페다.
- `음식점 > 간식 > 제과,베이커리`는 디저트다.
- `음식점 > 양식 > 햄버거`는 양식이다.
- `음식점 > 뷔페 > 한식뷔페`는 별미다. 뒤에 `한식`이라는 글자가 있어도 두 번째 마디는 `뷔페`다.

현재 확인한 별미의 두 번째 마디에는 `아시아음식`, `뷔페`, `퓨전요리`, `치킨`, `샤브샤브`,
`패스트푸드`, `패밀리레스토랑`, `샐러드`, `기사식당`, `구내식당`, `도시락`, `철판요리`, `푸드코트`가 있다.
이 목록은 예시다. 코드가 이 이름들을 따로 나열해 검사하는 것은 아니며, 음식점 8종에 없는 새로운 두 번째 마디도 별미로 분류한다.

단독 이름도 마디 전체가 정확히 일치해야 한다. `한식`은 한식이지만, 단독 `해물,생선`이나 `돈까스,우동`은 기타다.
코드에 없는 음식 이름을 의미상 비슷한 칩으로 추정해서 넣지 않는다.

### 문화/여가에 포함하는 카카오 경로

다음 11개 경로는 경로 자체와 하위 경로를 모두 문화/여가로 분류한다.

| 허용 경로 | 포함되는 원문의 예시 |
| --- | --- |
| `문화,예술` | `문화,예술 > 문화시설 > 미술관`, `문화,예술 > 도서 > 서점` |
| `여행` | `여행 > 관광,명소 > 문화유적 > 고궁,궁`, `여행 > 숙박 > 호텔` |
| `스포츠,레저` | `스포츠,레저 > 골프 > 골프장` |
| `이슈 > 이벤트` | `이슈 > 이벤트 > 팝업스토어` |
| `교육,학문 > 학습시설 > 도서관` | 해당 경로 자체와 `국공립도서관`, `작은도서관` 등 하위 경로 |
| `가정,생활 > 여가시설` | `가정,생활 > 여가시설 > 만화방 > 만화카페` |
| `가정,생활 > 목욕탕,사우나` | `가정,생활 > 목욕탕,사우나 > 찜질방` |
| `가정,생활 > 복합쇼핑몰` | 해당 경로 자체와 하위 경로 |
| `가정,생활 > 백화점` | `가정,생활 > 백화점 > 롯데백화점` |
| `가정,생활 > 생활용품점` | `가정,생활 > 생활용품점 > 인테리어장식판매` |
| `가정,생활 > 문구,사무용품` | `가정,생활 > 문구,사무용품 > 디자인문구` |

`문화,예술`, `여행`, `스포츠,레저`는 첫 마디 전체를 허용한다.
예를 들어 `문화,예술 > 사진 > 사진관,포토스튜디오`도 문화/여가이며, `여행 > 숙박` 아래 숙소도 모두 포함한다.
`이슈 > 이벤트`와 `가정,생활 > 목욕탕,사우나` 역시 표에 든 예시 외의 하위 경로를 허용한다.

단독 `관광명소`는 별도 규칙으로 문화/여가에 포함한다. 이 규칙은 한 마디 값에만 적용한다.

반면 `가정,생활` 전체를 허용하지는 않는다.
`가정,생활 > 미용 > 네일샵`이나 `가정,생활 > 패션 > 의류판매`는 위 허용 경로에 없으므로 기타다.
보드카페나 소품샵도 장소 이름만으로 문화/여가에 넣지 않는다.
원문이 `음식점 > 카페`이면 카페이고, `가정,생활 > 생활용품점`이면 문화/여가다.

## 규칙을 적용하는 순서와 경계 조건

앞에서 결과가 정해지면 뒤의 규칙은 적용하지 않는다.

1. 원문이 null, 빈 문자열, 공백뿐인 문자열이면 기타로 분류한다.
2. `>`로 마디를 나누고 각 마디의 앞뒤 공백을 제거한다. 중간이나 마지막을 포함해 빈 마디가 하나라도 있으면 기타로 분류한다.
3. 첫 마디가 `음식점`이면 음식점 8종 또는 별미로 분류한다. 단독 `음식점`도 별미다.
4. 단독 `관광명소`이거나 문화/여가 허용 경로에 맞으면 문화/여가로 분류한다.
5. 한 마디 원문이면 음식점 8종의 단독 이름 대응표를 확인한다.
6. 나머지는 기타로 분류한다.

분류에는 마디별로 공백을 제거한 값을 사용한다.
예를 들어 `  음식점  >  카페  `는 카페지만, `음식점 >`나 `음식점 >   > 카페`는 빈 마디가 있어 기타다.
문화/여가의 경로 비교도 첫 마디부터 마디 전체가 일치해야 한다.

| 원문 | 결과 | 분류 이유 |
| --- | --- | --- |
| `음식점` | 별미 | 첫 마디는 음식점이고 음식 종류는 없다. |
| `음식점 > 패스트푸드` | 별미 | 음식점 8종에 없는 두 번째 마디다. |
| `가정,생활 > 여가시설 > 만화방 > 만화카페` | 문화/여가 | 이름에 카페가 있어도 여가시설 경로다. |
| `여행 > 숙박 > 호텔` | 문화/여가 | 여행의 하위 경로다. |
| `한식` | 한식 | 단독 이름 대응표에 있다. |
| `돈까스,우동` | 기타 | 단독 이름 대응표에 없다. |
| `관광명소` | 문화/여가 | 한 마디 관광명소의 별도 규칙이다. |
| `서비스,산업 > 식품 > 식품가공,제조` | 기타 | 음식과 관련돼 있어도 음식점이나 문화/여가 허용 경로가 아니다. |

## 원문 저장과 응답

`places.category`에는 카카오 원문을 그대로 저장하고, 칩은 보관함 응답을 만들 때 계산한다.
`SavedPlaceService`가 분류기를 호출하고, `SavedPlaceResponse`는 분류된 값을 받아 응답 필드만 만든다.

| 응답 필드 | 의미 |
| --- | --- |
| `category` | DB에 저장된 카카오 원문. null과 공백도 그대로 유지한다. |
| `categoryCode` | 여기담 칩 코드. 예: `CAFE` |
| `categoryName` | 여기담 칩 표시 이름. 예: `카페` |

칩을 DB에 따로 저장하지 않으므로 매핑 기준이 바뀌어도 카카오 원문을 다시 기록할 필요가 없다.
변경된 분류기로 생성하는 보관함 응답부터 새 기준을 적용한다.
기존 앱 2.1.0이 원문을 사용하므로 `category` 필드는 유지한다.

`GET /api/v1/place-categories`는 비회원도 조회할 수 있으며, 저장된 장소 유무와 관계없이 11개 칩을 정해진 순서로 반환한다.
이 목록과 보관함 응답은 같은 `PlaceCategory`의 코드와 이름을 사용한다.

변경할 때는 다음 내용을 함께 남긴다.

1. **바꾸는 이유**: 저장 분포의 변화, 사용자 요구 등 판단 근거와 자료의 조회 시점을 기록한다. 장소 수와 저장 행 수를 구분한다.
2. **바뀌는 범위**: 어떤 카카오 경로가 어느 칩으로 이동하는지, 경로 자체만 바꾸는지 하위 전체를 포함하는지 정한다. 기존 코드나 순서를 바꾸면 앱이 사용하는 값도 함께 확인한다.
3. **검증할 사례**: 운영 원문에서 변경되는 대표 사례와 기존 분류를 유지해야 하는 인접 사례를 골라 테스트한다. 모든 브랜드 원문을 반복해서 넣기보다 분류 기준마다 필요한 사례를 남긴다.
4. **영향 확인**: 같은 시점의 데이터에 변경 전후 규칙을 적용해 칩별 장소 수와 저장 행 수를 비교한다. 기준을 바꾼 경우 분류기 테스트와 관련 API 테스트를 실행하고, 이 문서의 매핑과 변경 이력을 갱신한다.
