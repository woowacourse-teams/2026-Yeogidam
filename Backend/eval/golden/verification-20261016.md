# 전체 장소 골든셋 재검증 (2026-10-16)

## 대상과 검증 범위

음식점, 카페, 소품샵, 서점, 전시회 개최 장소, 공원, 관광지, 숙소, 학교 등 지도에서 식별할 수 있는 고정된 장소를 대상으로 한다. 게시물이 직접 소개하는 장소를 모으며, 배경 간판, 상품 브랜드, 경품으로 언급한 시설을 자동으로 소개 장소에 추가하지 않는다. 구체적인 지점이 없는 브랜드나 지역명만으로 가게를 만들지 않는다.

기존 40개 게시물의 공개 원문과 미디어를 다시 조회했다. 38건에서 원본 목록과 해당 미디어 전부를 확보했다. 캐러셀은 전체 이미지를 대조했고, 영상 27건은 캡션과 2초 간격 프레임의 자막/OCR을 대조했다. 음성 전체를 별도 전사한 검증은 아니므로, 화면과 캡션에 없는 음성 단서는 완전하게 검증했다고 주장하지 않는다.

C015와 C021은 공개 embed와 로그인 없는 공개 조회에서 미디어 원본을 확보하지 못했다. 기존 정답은 이력으로 보존하며 재검증 완료로 표시하지 않는다. 접근하지 못한 자료나 지점이 불명확한 자료를 모델 추측으로 채우지 않는다.

## 데이터와 이력 관리

현재 정답은 기존 `cases.csv`에서 수정한다. 이 문서에 장소별 상세 근거와 원본 미디어 목록을 함께 기록한다. 음식점 기준의 이전 정답과 채점표는 별도 복사본을 만들지 않고 Git 이력에서 확인한다. 기준 커밋은 `4e4b7c8c52f793f74041876d5a845b7cea9f2543`이다. 파일 이름의 날짜는 최초 작성일이며 본문은 최신 검증 결과로 갱신한다.

현재 지도 ID가 기록된 항목은 236개다. 원본 접근 불가 2건의 과거 ID를 포함한 수치이며, 신규 검증 완료를 뜻하지 않는다. 검증 상태는 `VERIFIED` 28건, `PARTIAL` 10건, `SOURCE_UNAVAILABLE` 2건이다. 검증 완료 28건에는 지도 정답 46개가 있다. 미확정 사례의 잠정 예측은 원시 결과와 진단 목록에 남기며 정답률/오탐 합계에서 제외한다.

## 지도 연결 판정

| mapping_status | 뜻 |
|---|---|
| MATCHED | 원본의 이름·지역·주소와 카카오 검색 결과를 대조해 ID를 확정함 |
| WEB_ONLY | 카카오 공식 장소 페이지에서 이름·주소를 확인했으나 검색 API에서 해당 ID를 확인하지 못함 |
| NOT_FOUND | 원본 소개는 확인했으나 같은 장소의 지도 ID를 확정하지 못함. 소개 목록에서 삭제하지 않음 |
| AMBIGUOUS | 지점·구간·이전 이력 등이 불명확해 검색 1위로 확정하지 않음 |
| UNIDENTIFIED | 실제 시설 소개는 있으나 상호를 확인하지 못함 |
| OUTSIDE_COVERAGE | 일본 대마도 등 국내 카카오 지도 ID로 임의 대체할 수 없는 장소 |
| SOURCE_UNAVAILABLE | 이번 원본 재검증을 못 했으며 과거 기록만 보존함 |

`WEB_ONLY`는 검증에 사용한 검색어로 API에서 확인하지 못했다는 뜻이며 모든 검색어로 불가능하다는 뜻은 아니다. `NOT_FOUND`는 장소가 존재하지 않는다는 뜻이 아니다. `PARTIAL`과 `SOURCE_UNAVAILABLE`은 정답이 완전하지 않을 수 있어 통계에서 제외한다. 정답이 비어 있는 `none`도 원본에 장소가 없다는 뜻과 같지 않다. 지도 저장 대상으로 확정된 ID가 없는 사례이며, 소개 항목과 미확정 사유를 별도로 확인해야 한다.

ID는 같은 상호의 다른 지점으로 대체하지 않는다. 본체 대신 주차장, 안내소, 입점 가게를 붙이지 않는다. 원본이 전시회 개최 시설이나 건물 내부의 만남 장소를 명시하면 그 시설 자체의 ID로 정규화하고 근거를 남긴다. 동일 주소와 이름을 대조해 같은 장소로 검증한 중복 지도 ID만 `accepted_kakao_aliases`로 허용한다. 현재 LDB와 원문 영문명 Low Deep Being still의 동일 주소 사례 한 건에만 적용한다.

## 실제 평가 해석

운영 추출 코드는 이번 작업에서 바꾸지 않는다. 캡션에 한 곳이라도 매칭되면 첨부를 읽지 않는 흐름이므로 원본 소개 목록의 일부를 놓칠 수 있다. 전체 장소 목록을 정답에 반영하는 것과 운영이 모든 장소를 맞히는 것은 별도 문제다.

API 장애는 정상 빈 결과와 구분한다. Python은 세 입력 변형을 비교하고 Java `evalTest`는 운영 흐름을 평가한다. 둘 다 현재 `cases.csv`의 전체 장소 정답을 사용한다. 실제 실행 결과와 남은 누락은 `../results/summary.md` 및 `../results/both.json`에 남긴다.
