## 대상과 고른 기준

앱 회원이 공유한 게시물 가운데 운영 추출이 틀린 장소를 붙였거나 실패했는데, 사람이 정답을 확인한 게시물을 골랐다. 열과 판정 규칙은 기존 `cases.csv`와 `verification-20261016.md`를 그대로 따르고, 사례 번호는 `U001`부터 쓴다.

## 검증 방법

- 단일 장소 32건과 장소가 없는 글 9건은 캡션과 미디어 전부(캐러셀 이미지 전체, 영상은 2초 간격 프레임)를 다시 읽어, 소개 장소가 정답과 같고 빠진 장소가 없는지 봤다. 음성은 듣지 않았으므로 말로만 나온 상호는 놓쳤을 수 있다.
- 미디어는 seed-data가 받아 둔 것을 썼고, 없던 11건은 같은 방법(로그인 없는 공개 페이지, 요청 사이 1.5초)으로 받아 data-migration 작업 폴더에만 두었다.
- 목록 사례는 seed-data가 슬라이드와 프레임으로 칸마다 확정한 값을 쓴다. seed-data가 장소를 정하지 않은 칸은 카카오에 없으면 NOT_FOUND, 지점을 가를 수 없으면 AMBIGUOUS로 적는다.
- U016 광안리 소품샵 목록은 seed-data 값이 없어서 영상 프레임 28장의 자막으로 여섯 칸을 정했고, 카카오 ID는 키워드 API 검색과 카카오맵 상세(영업 상태, 장소 키워드, 블로그 후기)로 확인했다.
- 카카오 ID는 seed-data 감사가 정한 값이다. 2026-11-10에 카카오 키워드 검색 API로 「이름」과 「시군구 + 이름」을 검색해 첫 쪽 15개 안에 없으면 `kakao_api_missing_ids`에 넣고 연결 상태를 WEB_ONLY로 적었다(정답 120곳 가운데 16곳).
- 소개 장소가 모두 MATCHED나 WEB_ONLY이면 VERIFIED이고, NOT_FOUND, AMBIGUOUS, UNIDENTIFIED, OUTSIDE_COVERAGE가 하나라도 있으면 PARTIAL이다. 장소를 소개하지 않는 글은 정답이 빈 VERIFIED none이다.
- 상호가 인스타그램 위치 태그나 계정 태그에만 있는 두 사례(U003, U024)는 kind를 미디어 종류로 두고 evidence에 태그를 적었다. 운영 추출은 캡션과 미디어만 Gemini에 보내고 두 태그를 넘기지 않는다.
- 캡션 원문, 회원 정보, @계정은 옮기지 않았다.

## 해외

해외 게시물은 overseas-places가 2026-11-09에 같은 회원 공유에서 만든 `overseas-cases.csv`(해외 21건, 국내 대조 3건, Google 장소 ID 정답)를 그대로 쓴다. 해외 회원 게시물 21개(실패 17, 국내 가게가 붙은 성공 4)가 모두 들어 있고, `overseas-cases.csv`는 아직 커밋 전이라 사본을 `user-overseas-cases.csv`로 함께 둔다. `user-cases.csv`에는 국내 가게가 붙은 해외 성공 게시물 4건만 정답이 빈 PARTIAL none으로 넣었다(기존 C039와 같은 처리).
